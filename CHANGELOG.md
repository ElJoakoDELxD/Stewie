# Changelog

One entry per release, newest first.

## Unreleased

An agent's memory is a core and categories. `memory/core.md` and `INDEX.md` are what every chat reads. The core is read whole and never compressed: at most 300 words, each item one line holding one statement, at most 280 bytes. The index fits itself to 400 words: open items always, then the newest entries of any category, the older ones counted in a line per category; everything else lives one file per item in `lessons/`, `decisions/`, `open/`, `references/` or `projects/`, each following its folder's `_schema.md`. `memory check` holds every file to its schema, and `memory index` writes `INDEX.md`, which lists only live entries and nobody edits by hand; `memory check` fails when open items alone fill it. A lesson whose error happens a third time is escalated to `.claude/hooks/lessons/`, which blocks the call; `git-runs-alone` is the first.

The code is held to a lint bar in CI: `tests/lint.sh` runs shellcheck at warning level on every `.sh` file, every script in `tools/bin` and the shipped socat wrapper, and ruff on every Python file, and fails on any finding. ruff is pinned by hash in `tests/lint-requirements.txt`; shellcheck comes from the runner. The one rule set aside, unused variables in the benches, says why in `tests/.shellcheckrc`.

The gatekeeper is calibrated. `tests/gatekeeper-cases/` holds 50 cases with the verdict each should get, built in the transcript format Claude Code writes, and `record.json` holds what the gatekeeper's prompt and model answered to each. The bench fails when the record is of another prompt or model, when a recorded verdict is not what its answer says, or when missed blocks pass 15% of the cases that should block or false blocks 10% of those that should pass. The run missed none of 20 and blocked none of 30 wrongly, one run each, which bounds the true rates to 14% and 10% at 95%. The judge was a subagent on the same model given the same prompt, not the hook itself. A baseline without the criterion, on 22 of the cases, erred only once, approving a bare yes to two questions: most of these cases test plain judgment, not the criterion.

A skill's description says what it is for and when to use it, never its steps: an agent may follow a summary instead of reading the skill. `orchestrate` gives the delegate and the checker the person's words as typed, not only a summary of them. A description Claude Code keeps out of context is no longer counted at start, which now reads 6422 bytes.

The machinery is held to evidence: `5s machinery` keeps a piece only if it shows that it acts. `tests/mutation.sh` makes each hook, tool, the gatekeeper's criterion and the sandbox kit's scripts do nothing, and needs some bench to fail; a workflow runs it when they change. Every trigger carries an `example` it fires on, among the calls `recall.sh` is wired to hear, which `memory triggers` and `memory check` verify. Every CI step can fail, so the redundancy report left CI for the `5s` shine step, with a bench of its own, and `test-code-only.sh` fails when no file it lists exists to read. A reminder no longer quotes a CLAUDE.md line, which is already loaded; it still quotes a rule from any other file. A lesson's `unless` stands it down where the latest isolation record, read as a record and not as text, is that text: `git-runs-alone` no longer blocks in a cloud container, where a lone git call was seen running inside the sandbox too.

Every delegation names its model. `delegation-model.sh` blocks an `Agent` call without a `model`, which would otherwise inherit the session's, the most expensive, in silence; its message gives when a smaller model pays. Only `malicious-code-review` and the Elephant-Goldfish reviewers (`egm-*`), whose review is the safeguard, inherit on purpose.

A chat knows how full its context window is. `tools/bin/context` reads the usage the transcript records for the latest turn, and `context.sh`, at each message, says nothing below half and, past 50%, 70% and 85%, says to run the handoff and offer a new chat: a long chat costs more every turn and fails when the window fills. Its text changes only between bands, so it does not break the prompt cache. The handoff gives each memory item its source, a commit, `file:line` or a URL, so a summary can be opened back to its detail. The canon can withdraw a release with a tag `withdrawn/v<x.y.z>`: a copy is not offered it, and a copy on it is told. These add 47 words to the governing prose, and its ceiling rises to match: they are new rules, not a repeat of old ones, and 5s trims what is said twice, not what is new.

The daily use holds. The handoff commits before it pulls: `git pull --rebase` refused to run over the unstaged memory it had just written. The handoff writes the chat's next step as an item in `open/`, where a new chat finds it in `INDEX.md`: it cannot read another chat's file. At the end of each turn, `autosave.sh` commits what changed in `.agent/` as `<agent>: autosave` and pushes it with an explicit `HEAD:refs/heads/agent/<name>`, so a closed tab loses nothing; it never blocks, and says so in one line when a push fails. It stays silent when `.agent` is a symbolic link, a separate clone, or in a merge, cherry-pick or revert. It commits but does not push when origin is the canon, since memory reaches a public branch only through the leak-check, or when the branch is not on origin yet: the first push is the handoff's. A canon with no `v*` tag is reported as having published no release yet, not as one that did not answer. A copy can create its custodian: `attach custodian` found no branch in a fresh copy, since onboarding made only `agent/<name>`; the onboard skill now creates the orphan branch `custodian` with its memory when the person asks for it, and autosave commits the custodian but leaves its push to the person's yes. Its steps raise the word budget to 7072. A bench's fixture no longer carries `.claude/worktrees` or `settings.local.json` from the checkout it runs in.

`CLAUDE.md` keeps only what the current model needs, by the removal test. Removed, and restorable each by its line: that git calls start with `git` and run alone, never chained, since the `git-runs-alone` lesson blocks a chained one and says why, except in a cloud container, where its `unless` stands it down, and the handoff already gives each `git -C .agent` call; that a refused host stays refused until the chat restarts, since `knowledge/lessons/refused-host.md` says it when a call is refused; that the third time an error happens the work stops, since `recall.sh` says it on the third error and the lesson schema escalates a lesson recalled a third time; that an improvement goes as far as it serves, since `rules/changing-the-system.md` gives its levels and the table points there; and that a reply proposes at most one thing, or a reflection, now only that a proposal says its cost and asks before spending it. Kept, since nothing else says them: that a git call never runs beside a parallel sandboxed call, which no hook can see, and that a fix is evaluated inward and outward before it is applied. The start falls to 5824 bytes and the whole system to 6957 words, and both ceilings fall with them.

The header comes without a tool call. `header.sh`, at each message of the person, runs `clock | header` with the transcript and session the hook input names, and adds its line to the context, with any `DESFASE`; the reply copies it, and runs `clock | header` only when no line came. It never blocks a message: on any error it says nothing. The line changes every minute by design, so it is kept to one short line, the only text the prompt cache cannot reuse. The row that says so adds 79 bytes to the start and 14 words to the system, and both ceilings rise to 5903 bytes and 6971 words: it saves a tool call at every reply. That line is printed before the turn has a model, so its model field reads `?·?`, which the row says is expected; the custodian reads its model from `clock | header` run in the turn, and these two notes raise the ceilings to 5982 bytes and 7006 words. `claude-fable-5-2` joins the models that may act as the custodian, on its published evaluation, the *Claude Fable 5.2 and Mythos 5.2 System Card*; its row adds 15 words, since a listed model needs its evaluation cited.

**Migrating an agent's memory (format 1 to 2)**, on the agent's own branch and only with the person's consent:

1. Copy `memory/_example/memory/` from this release into `.agent/memory/`, without overwriting files that exist, except each `_schema.md`, which this release replaces.
2. Move what every chat needs from `MEMORY.md` into `core.md`, and each other entry into one file in its category, with the fields its `_schema.md` requires. `backlog.md` items become files in `open/`, with `owner: person` or `owner: agent`; `delegations.md` moves to `references/delegations.md`.
3. Delete `MEMORY.md` and `backlog.md`, run `memory index`, and repeat `memory check` until it reports no problem.
4. Give each lesson's `trigger` an `example` it fires on; `memory check` names each one that has none.

## 2.0.0 — first public release

The first public release: a persistent colleague made of Claude Code and the person's own GitHub repository. Each agent is one file on its own branch, with its memory, its chat notes and its work beside it; its declared effects are its permissions. A new chat picks an agent, attaches its branch, and saves to it before it ends. The template lives only in `main`, and a custodian keeps it a stable product: every change is a release, with benches that run in CI.

The agent no longer commits or pushes `.agent/` itself. In a cloud session the Bash sandbox is on once an agent is attached, and a `git commit` there cannot reach the container's commit-signing service on loopback, which no sandbox setting on Linux opens, so a new user's first save never happened. Hooks run outside the Bash sandbox, so `autosave.sh` now does all of it at the end of each turn: it reads `transcript_path` and `session_id` from its input and makes a branch's first push when this chat declared that agent with `header --declare`, and an undeclared branch not on origin stays committed and unpushed, saying so in one line. When the branch is on origin it fetches it and rebases onto what other chats pushed before it pushes; on a conflict it aborts the rebase and leaves the commit unpushed, in one line. Its limits: every push needs `stewie_identity` to name the agent whose branch `.agent` is on, and the first push needs the declaration itself in the transcript, which `stewie_identity ... strict` gives without the chat-file fallback other callers keep; it pushes to origin's fetch URL named on the command line, and not at all when git config holds a `pushurl` or `pushInsteadOf` entry or the canon cannot be read; ls-remote, fetch, rebase and push are capped at 10, 15, 10 and 20 seconds, inside the hook's 60. Each refusal commits, says in one line that the work is saved on this machine only, and asks the agent to tell the person in plain words, never to run git; `attach` says the same of uncommitted work. The onboard and handoff skills and `rules/ending-a-session.md` lose their `git add`, `commit`, `pull --rebase` and `push` steps: the agent only writes the files, and tells the person when the autosave says it could not push. The custodian's push still waits for the person's yes, a turn after autosave commits it. The steps are shorter than the git calls they replace. In a cloud onboarding the agent ran `attach` and `header --declare` in one call, before the sandbox was on, then the declaration alone, and the autosave still refused the first push as undeclared: the reader took only the bare command with an output that was the mark and nothing else. A declaration now counts in the forms the same act takes: `header`, `tools/bin/header`, `./tools/bin/header` or this copy's absolute path to it, with whitespace around the command, and the mark as one whole line of its output among a stderr line or a note the harness adds. Chained, piped, with another argument, from another checkout or printed by `echo`, it still does not. `attach` ends with the next step, `Next, in a call of its own: header --declare agent=<name>`, and the onboard skill says to do what that line says. `header --declare` refuses a call chained with others, read from its own record in the transcript, or made before the sandbox is on, and says to run it again alone, in its own call; it fails when it cannot write the chat's file. The word budget falls to 6991.
